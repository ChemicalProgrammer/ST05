# ST

Aplicación web con Apps Script, almacenamiento en Drive e integración con Gemini.

Los cambios permanecen en el borrador del navegador hasta guardar en Drive: [configuración y funcionamiento](docs/CLOUD_SAVING.md). No se requiere un auxiliar local.

- Textos de interfaz: `apps-script/TextResources.gs`.
- Colores, tipografía, tamaños y espaciado: `apps-script/DesignTokens.html`.
- Vistas y controladores: módulos en `apps-script/`.
- Reconstrucción desde Gemini Pro (chat): [Gemini](Gemini/README.md).
- Documentación histórica: `docs/`.
- Reconstrucción con Gemini Code Assist: [Visual Code](Visual%20Code/docs/README.md).

`npm run build:apps-script` actualiza los adaptadores del motor (`SimulationEngine.html` y `ScenarioEngine.gs`); requiere Python 3 en la máquina de desarrollo para incluir el paquete SimPy. El despliegue usa todos los módulos `.gs` y `.html` de `apps-script/` y su manifiesto. Si existen `Code.gs` e `Index.html` en un proyecto de Apps Script anterior, elimínalos: ya no forman parte del despliegue. `npm test` ejecuta las pruebas.

En **Advance → Settings → Simulation**, el motor actual permanece por defecto y se puede elegir **DES · Python / SimPy (experimental)** por simulación. Se ejecuta en el navegador con Pyodide, sin Google Cloud, y necesita descargar el runtime por HTTPS la primera vez. El OEE y What-If del prototipo aún no están validados. [Alcance, límites y pruebas](docs/35_BROWSER_SIMPY_ENGINE.md).

En **Line Setup**, cada equipo permite editar **MTBF (min)** y **MTTR (min)** y activar/desactivar **Failures enabled**. Los valores alimentan `noiseProfile.reliability` y se conservan en `processData.equipment`; desactivar fallas conserva los tiempos para volver a activarlas.

**Import JSON**, junto a **Import Sheet**, permite abrir un archivo JSON (hasta 6 MB) o pegar su contenido. **Edit JSON**, en la vista JSON, abre la configuración de la simulación activa. Ambos usan un borrador independiente: **Validate and Apply** valida y actualiza la interfaz; **Cancel** descarta el borrador. Se acepta el formato exportado `st-line-configuration-v1` o un objeto con `equipment` y, opcionalmente, `dynamicConfig`. Se validan la estructura, los identificadores, las reglas físicas y la confiabilidad. Esta interfaz requiere `tickSeconds: 0.25`.

La aplicación conserva la identidad del caso y la simulación, así como las otras simulaciones. La configuración compartida `engineConfig` y la unidad del caso deben coincidir. Aplicar una configuración descarta los resultados anteriores de la simulación activa y activa el guardado automático; los errores de guardado siguen disponibles para reintento.

Un JSON con `schema: "st-line-configuration-v1"` e `importMode: "DRAFT"` permite cargar una configuración completa como borrador editable cuando faltan datos físicos de conveyors. Los pendientes aparecen antes de aplicar; la validación del motor sigue impidiendo una simulación con geometría incompleta o incompatible. La importación normal conserva sus comprobaciones completas. [Caso E: archivo compatible, alcance y pendientes](docs/CASE_E_JSON_IMPORT.md).

La lista de casos incluye un botón **Clone case** en cada fila o tarjeta. Crea una copia independiente con sus simulaciones y resultados guardados, sin modificar el caso original. Al actualizar una instalación anterior, elimina también `ReferenceCaseFactory.gs` de Apps Script: ya no forma parte de la aplicación.

**Line Setup → Export JSON** guarda únicamente los parámetros de entrada de la simulación activa. En **Comparisons**, selecciona dos simulaciones y usa **Export** para obtener JSON de ambas configuraciones, resultados guardados y estadísticas de todas las réplicas, o un reporte HTML/PDF. En **What-If**, **Export** ofrece JSON con las propuestas visibles, comprobaciones y evidencia de la simulación seleccionada, además de HTML/PDF. Los JSON de análisis son reportes de datos y no son archivos de configuración para **Import JSON**. Los replays y registros de eventos no forman parte de estos reportes.

En una simulación con varias rondas, cada una usa los mismos eventos programados y una semilla distinta. Cuando el navegador admite workers, también la primera ronda se calcula en un worker y transmite sus datos a la interfaz; las siguientes pueden comenzar en paralelo. El límite de concurrencia considera los procesadores lógicos, la memoria disponible y la reserva para interfaz y reproducción. Las rondas de fondo conservan sus estadísticas sin generar todos los frames. Si se necesita la reproducción de una ronda representativa distinta de la primera, se calcula adicionalmente; **Summary only** omite esa repetición y mantiene las mismas estadísticas del lote. Un control de equipo añadido a la primera ronda recalcula todas las rondas. Al guardar, se limita el número de frames de las reproducciones disponibles para reducir el tamaño del caso.

**Settings → Simulation → Calculation → Numerical resolution** permite elegir **Precise** (predeterminado), **Balanced** o **Fast (approximate)**. En el motor actual, con permanencia interna activa, los pasos máximos son respectivamente 1/120, 1/60 y 1/20 segundos. Un día requiere aproximadamente 10.37, 5.18 o 1.73 millones de pasos. Cambiar esta resolución modifica la aproximación temporal, puede cambiar los resultados y requiere recalcular la base; no modifica la duración simulada. Todas las rondas, la reproducción numérica y los escenarios heredan la misma resolución. Los resultados guardan el paso efectivo en `numerics`. Este ajuste no modifica el motor experimental SimPy.

**Settings → Simulation → Scenario search → Search speed** controla la exploración por caso, independientemente de DOE/ANOVA. **Balanced search** conserva los presupuestos anteriores. **Fast search** usa hasta 5 minutos para explorar, 15 minutos para preseleccionar, un máximo de 48 candidatos ordinarios y un finalista de flujo a horizonte completo. **Thorough search** amplía los horizontes y presupuestos. El límite ordinario no cuenta la selección automática de factores, las combinaciones DOE ni la confirmación. Los cambios de confiabilidad y los eventos programados mantienen sus protecciones y pueden exigir más finalistas completos.

La búsqueda compara cada candidato con una base calculada para el mismo horizonte y resolución. Los períodos abreviados sirven para seleccionar hipótesis; la clasificación final y la confirmación independiente conservan el horizonte completo de la base, con un mínimo de 30 minutos. La confirmación mantiene el plan de réplicas y los criterios estadísticos. No existe un período corto universal que garantice detectar mejoras, especialmente si el arranque ocupa buena parte del período o las fallas son poco frecuentes. Cambiar la velocidad de búsqueda marca sus resultados para recalcular sin invalidar la simulación numérica base; cambiar la resolución numérica sí invalida esa base. Los escenarios siguen requiriendo una simulación numérica completa y vigente.

En **Case Gallery → Settings**, aparecen **Appearance** y **Storage**, además de **Gemini** exclusivamente en Advance; **Case** y **Simulation** requieren un caso abierto. En **Advance → Settings → Storage → Factory reset**, **Reset app** limpia la conexión de Drive, llave y configuración de Gemini de la cuenta y preferencias de este navegador, y vuelve al inicio de sesión. Primero cierra el caso y conserva el folder ID. Los archivos, resultados y `cases-index-<email>.json` de Drive permanecen: inicia sesión con la misma cuenta y vuelve a introducir el mismo folder ID para recuperar los casos. El modo vuelve al valor predeterminado del despliegue; no se alteran las propiedades globales ni otras cuentas.

**Gemini**, su asistente y todas sus opciones de configuración sólo están disponibles en **Advance**, tanto en un caso abierto como en **Case Gallery**. Cambiar a Basic cierra el chat y conserva la llave, las opciones y el historial. En Gallery permite consultas de uso de la app sin enviar datos de casos; ese historial vive únicamente en memoria durante la sesión y no se guarda en Drive. En un caso abierto, el checkbox **Case context** incluye la simulación seleccionada cuando está marcado; desmarcarlo permite consultas generales. El historial de Gallery permanece separado del historial de cada simulación.

Para compartir la app con configuraciones independientes, crea una implementación **Web app** con **Execute as → User accessing the web app** y acceso al grupo previsto (**dominio** o **usuarios con cuenta de Google**, según tu política). Cada usuario autoriza la app con su propia cuenta y configura su folder ID y llave Gemini en Settings. No uses **Execute as → Me**: ejecutaría las operaciones con los permisos del desarrollador. La app rechaza solicitudes cuando el usuario activo y el efectivo no coinciden, antes de leer configuraciones o Drive. El manifiesto declara `USER_ACCESSING`, pero debes verificar la implementación realmente compartida; subir archivos no cambia una URL `/exec` que sigue apuntando a una versión anterior. Settings acepta folder ID o URL de carpeta de Drive. El campo de llave muestra una máscara cuando está configurada; el servidor nunca devuelve la llave guardada.

Si falla el inicio de sesión, el diálogo distingue autorización incompleta, módulos faltantes y otros fallos internos, e indica la etapa y una referencia `LOGIN-…`. La configuración de arranque verifica identidad antes de leer datos privados. El manifiesto declara explícitamente los permisos existentes de identidad, Drive, Sheets y solicitudes a Gemini. Al actualizarlo, cada usuario debe autorizar los permisos solicitados desde la nueva implementación. Para probar con Gmail externo, la implementación debe permitir usuarios con cuenta Google y la política de Workspace debe permitir ese acceso; una implementación restringida al dominio no admite Gmail externo.


**Real data**, después de **Results**, conserva observaciones reales por caso y compara producción, flujo y eficiencia con el promedio de las rondas o una ronda seleccionada. Admite captura manual, importación JSON (incluido el registro archivado del Caso C), fuente y notas, tiempos y confiabilidad por equipo. Exporta JSON y un reporte HTML imprimible a PDF. Los períodos, unidades y definiciones incompatibles se señalan; editar observaciones conserva los resultados simulados. [Uso y contrato de datos](docs/REAL_DATA_COMPARISON.md).
